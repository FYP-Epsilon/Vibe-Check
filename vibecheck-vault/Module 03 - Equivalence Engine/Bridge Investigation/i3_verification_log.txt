PART 2 — Q2: is the self-referential sentinel fixable?
==============================================================================

== S1 (EXPERIMENT, answers Q2 for the P0 shape): NO — unfalsifiable for ANY lifting ==
  Any lifting that is FAITHFUL to task semantics enforces the invariant
      'every occurrence of done_T is preceded by start_T'.
  That invariant is LOGICALLY IDENTICAL to the property !done_T W start_T.
  Formally: intersect(negation of property, models satisfying invariant) = EMPTY.
      product states: 4;  --is-empty => EMPTY.
  => the P0 self-referential sentinel is unfalsifiable not because of a lifting
     DESIGN FLAW but because the property asks the code to contradict the very
     invariant that makes the lifting faithful. No construction can fix it.
     Session 2's reviewer was right about (b), and the result generalises to ALL
     constructions, including any future one.

== S2 (EXPERIMENT, the constructive half of the answer): ==
     CROSS-TASK properties ARE genuinely checkable under the same invariant.
  M01's P1 sequence-flow shape (ltlf_synthesizer.py:119,127-128) is
      !start(B) W done(A)
  which relates TWO DIFFERENT tasks. Under the faithful-lifting invariant
      (!done_A W start_A) & (!done_B W start_B)
  the negated property is still satisfiable:
      product NON-EMPTY; witness word from SPOT:
        alive & !done_A & start_A & start_B; cycle{!alive}
      (B starts in the same step A starts, before A is done -> real violation)
  Cross-checked with M01's OWN evaluate_ltlf over the 1979 faithful traces of
  length<=3 (of 4368 total):
      !done_A W start_A   -> {True}         UNFALSIFIABLE
      !start_B W done_A   -> {True,False}   FALSIFIABLE, witness [['start_B']]
  Two tools, two trace semantics (infinite-trace SPOT, finite-trace evaluate_ltlf),
  same verdict.

== S3 (EXPERIMENT): falsifiability of EVERY M01 property shape under faithful lifting ==
  Method: intersect(!translated_property, faithful-lifting invariant); non-empty=checkable.
      P0 self-ref  !done_A W start_A          UNFALSIFIABLE (vacuous)
      P1 seq flow  !start_B W done_A          FALSIFIABLE  (checkable)
      P1 XOR excl  G(done_A -> !done_B)       FALSIFIABLE  (checkable)
      P1 AND sync  G(start_A <-> start_B)     FALSIFIABLE  (checkable)
      P1 AND sync  G(done_A <-> done_B)       FALSIFIABLE  (checkable)
  => exactly ONE of the five shapes is inherently vacuous, and it is the P0 tier.
     The P1 tier carries all the genuine checking power.

== S4 (EXPERIMENT, confirms the brief's 'dangerous category'): ==
     an UNMATCHED atom on the RHS of a weak-until is a FALSE-POSITIVE generator.
  If done_A is never matched by the lifter, its AP is permanently false, so
      !start_B W done_A   collapses to   G(!start_B).
  Evaluated with M01's evaluate_ltlf:
      correct code, B starts, A's done unobservable -> FALSE (reports VIOLATION)
      correct code, B never starts                  -> TRUE
  => whenever start_B matches but done_A does not, CORRECT code is reported
     non-compliant. This is worse than vacuity: vacuity yields false GREEN,
     this yields false RED, and G5 shows the atoms are in different automata
     precisely when this shape arises.
